# 新增 N-API addon 包 + electron-demo-napi 最小 demo

不动 `electron-demo-cpp` 和 `gate_stream.exe`（保留作子进程方式对照），新增两样东西：

## 一、新增 `sdk/cpp-napi/` 包（@audiotse/gate-napi）

```
sdk/cpp-napi/
├── package.json     # devDeps: node-addon-api@^8, cmake-js@^7；无运行时依赖
├── CMakeLists.txt   # 独立构建根：编 ../cpp 的三个源文件 + addon 绑定
├── napi/addon.cc    # node-addon-api 绑定层（唯一新增 C++ 文件）
├── index.js         # JS 包装：SpeakerGate 类，API 与 sdk/web 同名同签名
├── index.d.ts       # 类型定义
├── build.ps1        # 激活 VS → 检查 sherpa 包 → npx cmake-js compile
└── README.md        # 构建方法、API 对照、串行调用约束
```

**CMake**：从 `sdk/cpp/CMakeLists.txt` 提取 sherpa-onnx 探测/导入块（15–61 行）为 `sdk/cpp/cmake/sherpa-onnx.cmake` 共享片段（路径锚定 cpp 目录，原 cpp 的 build.ps1 行为完全不变）；`cpp-napi/CMakeLists.txt` include 它并产出 `audiotse_gate_napi.node`（MODULE target，PREFIX "" SUFFIX ".node"），沿用 /utf-8、/MD、C++17、NAPI_VERSION=8，POST_BUILD 拷 4 个 sherpa dll（sherpa-onnx-cxx-api/c-api、onnxruntime、providers_shared）到 `.node` 同目录——libuv dlopen 用 LOAD_WITH_ALTERED_SEARCH_PATH，同目录 dll 可被解析。

**addon.cc 绑定层**：ObjectWrap 类 `Gate` 持 `shared_ptr<SpeakerGate>`；
- `createGate(config) -> Promise<Gate>`：AsyncWorker 内加载模型（~0.5s 不阻塞 JS 线程），失败 reject
- 异步方法（AsyncWorker + Promise）：`enrollChunk(Float32Array) -> {speechSeconds, enough}`、`finishEnroll() -> {speechSeconds}`、`accept(Float32Array) -> GateSegmentEvent[]`、`flush() -> GateSegmentEvent[]`
- 同步：`beginEnroll` / `reset` / `dispose`、getter `enrolled` / `effectiveThreshold`
- 事件对象 `{type:'segment', start, durationSeconds, similarity: number|null, accepted, samples: Float32Array}`，字段与 web SDK 完全一致（不再走 int16 量化）；异常 catch `std::exception` 转 Promise reject（中文 message 原样透出）

**index.js 包装**：require `.node` 前把其目录注入 `process.env.PATH`（dll 解析双保险）；`SpeakerGate` 类全部方法对齐 web SDK 签名（`static async create(config)` / `beginEnroll()` / `async enrollChunk/finishEnroll/accept/flush` / `reset()` / `dispose()` / getter）；内部 promise 链把异步调用串行化（SDK 要求串行调用）。

N-API ABI 稳定：`.node` 免重编译即可同时跑在 Node 18+ 与 Electron 41 主进程。

## 二、新增 `sdk/electron-demo-napi/` 最小 demo

- 结构复制 electron-demo-cpp：`package.json`（仅 electron devDep + start 脚本）、`preload.js` 与 `renderer/` 直接拷贝（本就与 web demo 逐字节相同，仅改窗口标题为「C++ NAPI SDK」）。
- `main/index.js` 新写（对齐 electron-demo-web 的结构，仅 require 路径不同）：`require('../../cpp-napi')` → `await SpeakerGate.create({vadModel, speakerModel})`，enrolling/monitoring 状态路由在主进程 JS，IPC 通道名与另两个 demo 完全一致，`gate:event` 透传含 `start` 的完整事件（对齐 web 版）。
- 附 `test-gate-napi.js`：不依赖麦克风的协议级自检——直连 NAPI SDK 跑 `app/samples/enroll_target.wav`（100ms 块流式注册）+ `mixed.wav`（流式监听 + flush），断言现有基准：enrolled≈3.78s、恰 2 段、start=1984 sim≈0.188 拒绝、start=97728 sim≈0.569 放行（该基准即 web SDK 对拍值，等价于双后端一致性验证）。

## 三、验证

1. `cd sdk/cpp-napi && npm install && .\build.ps1` 编译出 `.node` + 4 个 dll。
2. `node test-gate-napi.js`（electron-demo-napi 下）通过数值基准。
3. `cd sdk/electron-demo-napi && npm install && npm start` 启动验证 ready、无 dll 加载错误；**实时麦克风对比由你执行**——与 electron-demo-web 同时 `npm start`，两窗口共用麦克风，界面操作完全相同，肉眼看判定一致性。
